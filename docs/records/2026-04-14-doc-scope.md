# 文档修订范围记录

日期: `2026-04-14`

## 背景

本次根目录文档整理过程中，工作区同时存在一批尚未提交到 Git 的新增实现。

为了避免正式文档提前描述未提交代码，本记录明确约束本轮文档修订范围。

## 本次采用的边界

- 正式文档基线以 `git HEAD` 文件树为准。
- 统计方式以 `git ls-tree -r --name-only HEAD` 为主。
- 工作区未提交文件不写入根导航和组件总览。

## 本次调整的文件

- `readme.md`
- `COMPONENTS.md`

## 放置方式

仓库当前没有现成的通用过程文档目录。

模块说明文档采用“模块旁路 `.md`”方式，根目录文件负责总览；因此把这类修订边界、维护记录单独放入 `docs/records/`，可以避免:

- 污染根目录
- 混入正式组件说明
- 和模块实现文档混写

## 后续约定

- 根目录总览类文档默认只描述已提交内容。
- 若工作区存在较大的未提交实现，应先单独记录边界，再更新正式文档。
- 未提交实现如需说明，应放在独立记录文件中，而不是直接并入正式模块导航。
