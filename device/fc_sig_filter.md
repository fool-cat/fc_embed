# 信号滤波器选型与适用场景说明

本文档对应以下代码：

- [fc_sig_filter.h](./fc_sig_filter.h)
- [fc_sig_filter.c](./fc_sig_filter.c)

## 1. 当前框架的使用方式

`fc_sig` 的滤波机制比较简单直接：

1. 通过 [fc_sig_catch_filter()](./fc_sig.c#L38) 绑定一个滤波器对象和滤波函数
2. 在 [fc_sig_heart()](./fc_sig.c#L49) 中读取当前原始状态
3. 如果绑定了滤波器，就调用对应的 `filter_func`
4. 滤波函数返回的结果会写入 `sig->state_steady`

因此当前架构的特点是：

- `fc_sig` 只负责调度
- 具体滤波策略完全由 `fc_sig_filter.[ch]` 中的滤波器实现决定
- 扩展新的滤波方式时，不需要修改 `fc_sig` 主框架

每一种滤波器都保持同样的风格：

- 一个 `struct` 保存内部状态
- 一个 `init()` 负责初始化参数
- 一个 `filter()` 负责每次采样时更新状态并输出稳态

这种方式很适合嵌入式项目：

- 接口简单
- 不依赖动态内存
- 状态清晰
- 很容易按场景替换不同滤波器

## 2. 已有滤波器的特点与适用场景

### 2.1 `scale` 比例滤波器

接口：

- [fc_sig_filter_scale_init()](./fc_sig_filter.h#L38)
- [fc_sig_filter_scale()](./fc_sig_filter.h#L39)

实现特点：

- 对有效和无效分别计数
- 当前采样为有效时，会增加有效计数、减少无效计数
- 当前采样为无效时，会增加无效计数、减少有效计数
- 当计数达到一定比例关系后，才切换稳态

优点：

- 对短时间偶发反向抖动有一定容忍度
- 不会像严格连续计数那样被单次毛刺立即打断趋势

缺点：

- 参数直观性一般
- 在临界点持续抖动时，仍可能来回摇摆
- 实际工程里通常没有其他几种方式好调

适用场景：

- 原始信号总体有趋势，但中间会夹杂少量反向采样
- 希望“看整体倾向”，而不是要求严格连续一致
- 调试阶段想快速试一种相对宽松的策略

不太适合：

- 机械按键去抖
- 临界点长期高频抖动
- 对状态切换门槛要求明确的场景

### 2.2 `repeat` 连续重复滤波器

接口：

- [fc_sig_filter_repeat_init()](./fc_sig_filter.h#L54)
- [fc_sig_filter_repeat()](./fc_sig_filter.h#L55)

实现特点：

- 只有当前状态连续重复 `count_repeat` 次，才切换稳态
- 一旦采样跳到相反状态，对应连续计数就会被清零

优点：

- 逻辑最直观
- 很适合“必须连续稳定若干次才认定”的需求
- 对开关量去抖非常常用

缺点：

- 只要中间插入一次反向采样，连续计数就会中断
- 对零星毛刺较敏感

适用场景：

- 按键去抖
- 干接点输入
- 限位开关
- 霍尔开关
- 在状态边界附近会连续抖动，但最终会稳定到某一边的信号

推荐理解：

- 这是最通用、最容易整定的默认方案
- 如果没有更明确的需求，优先从它开始

### 2.3 `asym_repeat` 非对称连续重复滤波器

接口：

- [fc_sig_filter_asym_repeat_init()](./fc_sig_filter.h#L71)
- [fc_sig_filter_asym_repeat()](./fc_sig_filter.h#L72)

实现特点：

- 切换到有效态和切换到无效态，分别使用不同的重复计数
- 本质上仍然是连续重复滤波
- 只是把上下沿的确认门槛拆开了

优点：

- 很适合“吸合快、释放慢”或“释放快、吸合慢”的需求
- 比单一 `repeat` 更贴近真实应用

缺点：

- 参数比 `repeat` 多一个
- 如果需求本身对称，用它没有明显收益

适用场景：

- 传感器有效态要快速响应，但失效态要更保守
- 继电器触点或机械结构释放时抖动更严重
- 人机输入里“按下要快、松开要稳”
- 检测到报警要迅速进入，解除报警要多确认几次

典型例子：

- `count_valid_repeat = 2`
- `count_invalid_repeat = 6`

含义是：

- 连续 2 次有效就认定进入有效
- 连续 6 次无效才认定退出有效

### 2.4 `integrator` 积分滤波器

接口：

- [fc_sig_filter_integrator_init()](./fc_sig_filter.h#L88)
- [fc_sig_filter_integrator()](./fc_sig_filter.h#L89)

实现特点：

- 有效采样时，积分值加一
- 无效采样时，积分值减一
- 积分达到上阈值时输出有效
- 积分降到下阈值时输出无效
- 中间区域保持当前稳态

可以把它理解为：

- `repeat` 是“必须连续命中”
- `integrator` 是“整体趋势累计到一定程度”

优点：

- 对零星毛刺容忍度更高
- 单次反向抖动不会立刻把趋势全部打断
- 状态切换比较平滑

缺点：

- 参数直观性不如 `repeat`
- 需要理解“积分上限”和“阈值”的关系
- 如果采样频率太低，效果不一定比简单重复更明显

适用场景：

- 模拟量阈值化后的二值状态
- 传感器边缘区域会偶发跳变，但整体趋势比较明确
- 电流、电压、压力、温度等信号做二值判定
- 希望比 `repeat` 更抗毛刺，但又不想做复杂滤波

参数建议：

- `count_max` 表示积分总范围
- `count_threshold` 表示输出有效的门槛
- 当前实现要求 `count_threshold > count_max / 2`
- 这样可以保证有效阈值和无效阈值之间留出迟滞区

推荐整定思路：

- 想更稳：增大 `count_max`
- 想更快进入有效：适当减小 `count_threshold`
- 想更慢退出有效：增大 `count_threshold`

### 2.5 `window` 滑动窗口多数决滤波器

接口：

- [fc_sig_filter_window_init()](./fc_sig_filter.h#L106)
- [fc_sig_filter_window()](./fc_sig_filter.h#L107)

实现特点：

- 保存最近 `count_window` 次采样结果
- 统计其中有多少次为有效
- 有效次数达到阈值就输出有效
- 无效次数达到阈值就输出无效

优点：

- 非常适合固定周期采样
- 参数含义直观
- 很像“最近 N 次里多数是否赞成”
- 比单纯连续计数更能容忍穿插毛刺

缺点：

- 需要保存窗口历史
- 窗口没填满之前不会立刻形成完整判断
- 如果窗口过大，响应会变慢

适用场景：

- 周期轮询型数字输入
- 通讯采样后的状态判定
- 多次采样确认某个传感器是否真正触发
- 原始信号偶发跳变，但希望按“最近一段时间整体结果”判定

参数建议：

- 当前实现最多支持 32 个采样窗口
- 当前实现要求 `count_threshold > count_window / 2`
- 也就是严格多数决，避免有效和无效条件重叠

典型例子：

- `count_window = 8`
- `count_threshold = 5`

含义是：

- 最近 8 次采样里，有 5 次及以上有效则判定有效
- 最近 8 次采样里，有 5 次及以上无效则判定无效

## 3. 怎么选最合适

如果只想快速选型，可以按下面思路：

### 优先选 `repeat`

适合：

- 按键
- 干接点
- 限位
- 机械开关去抖

原因：

- 最容易理解
- 最容易调参数
- 最符合“连续稳定若干次才算”的工程直觉

### 上下沿需求不同，选 `asym_repeat`

适合：

- 进入状态要快，退出状态要稳
- 报警进入和报警解除要求不同
- 按下和松开特性明显不一致

### 有零星毛刺，但整体趋势明显，选 `integrator`

适合：

- 传感器阈值判断
- 模拟量二值化
- 偶发反向采样较多，但不想被单次毛刺打断

### 采样是固定周期，想做“最近 N 次多数决”，选 `window`

适合：

- 周期轮询采样
- 想让判定更统计化
- 希望兼顾稳定性和一定响应速度

### `scale` 放在补充方案

适合：

- 想尝试一种较宽松的比例型策略
- 已有项目中已经验证过它的参数

不建议作为首选：

- 因为通常没有 `repeat`、`asym_repeat`、`integrator`、`window` 直观

## 4. 参数整定建议

### 对 `repeat` / `asym_repeat`

经验上可以这样调：

- 抖动很轻：`2~3`
- 中等抖动：`4~6`
- 抖动很强：`6~10`

要点：

- 数值越大越稳
- 数值越大响应越慢

### 对 `integrator`

经验上可以从下面起步：

- `count_max = 6~16`
- `count_threshold = count_max / 2 + 1` 到 `count_max - 1`

要点：

- `count_max` 越大，整体越稳
- `count_threshold` 越大，进入有效越慢，但退出有效也会更保守

### 对 `window`

经验上可以从下面起步：

- `count_window = 5`，`count_threshold = 3`
- `count_window = 8`，`count_threshold = 5`
- `count_window = 10`，`count_threshold = 6`

要点：

- 窗口越大，越稳，但延迟越大
- 阈值越高，对切换越保守

## 5. 一个简单结论

如果按工程常用程度排序，大致可以这样理解：

1. `repeat` 是最常用的基础方案
2. `asym_repeat` 是最贴近真实项目需求的增强版
3. `integrator` 适合对抗零星毛刺
4. `window` 适合固定周期采样下做多数决
5. `scale` 可以保留，但通常不是首选

如果后面还要继续扩展，比较值得增加的方向通常是：

- 基于时间戳的“持续时长确认”滤波
- 带上下阈值的施密特触发式判定
- 面向模拟量的均值/中值后再二值化判定
