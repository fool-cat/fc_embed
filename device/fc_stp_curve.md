# 步进曲线理论与实现说明

本文档对应以下代码：

- [fc_stp_curve.h](./fc_stp_curve.h)
- [fc_stp_curve.c](./fc_stp_curve.c)

## 1. 当前框架的基本运行方式

`fc_stp_base` 的心跳函数 [fc_stp_base_heart()](./fc_stp_base.c#L38) 负责以下事情：

1. 按 `pulse_scale` 计数输出一个完整 step 脉冲
2. 每完成一个 step 后更新当前位置 `s_now`
3. 调用曲线函数计算“下一步应该使用的速度”
4. 通过 `freq_set()` 把这个速度换成底层定时器频率

因此，这一套架构的本质是：

- 速度是在“每走完一步”之后更新的
- 不是连续时间域实时更新
- 所以所有曲线最终都会体现为“离散步进的速度变化”

这意味着：

- 理论曲线再理想，逻辑分析仪上看到的速度曲线仍然会有台阶
- 但更合理的曲线模型，仍然能显著改善整体外形、机械冲击和稳定性

## 2. 四套曲线的理论区别

### 2.1 `ladder_curve`

接口：

- [ladder_curve_init()](./fc_stp_curve.h#L35)
- [ladder_curve_func()](./fc_stp_curve.h#L37)

实现思想：

- 每走一步，速度直接加上或减去一个固定增量
- 即：

```text
v(n+1) = v(n) + const
```

特点：

- 算法最简单
- 最省算力
- 但它更像“步数域线性变化”，不是标准时间域梯形
- 抓出来的速度-时间曲线通常不会是严格直线斜边

实现修正：

- 当前版本把离散加速段拆成了“前段 + 后段”两段
- 前段每步使用较大的速度增量 `a_now`
- 后段每步使用较小的速度增量 `a_back`
- 两段长度在 `ladder_curve_init()/START` 阶段一次性算好

这样做的原因是：

- `a_now` 原本是通过向上取整得到的
- 如果整段都用同一个 `a_now`
- 就可能比预期更早到达 `v_target`
- 后续再按固定 `s_acc_target` 减速时，就会在尾部提前掉到 `v_start`
- 于是最后几步会以最低速度拖尾

改成前后两段后：

- 总速度增量可以精确等于 `(v_target - v_start)`
- `NEXT` 阶段只需要根据“已走步数/剩余步数”取预计算好的步进增量
- 热路径里只做一次常量加/减，不再按 progress 反算当前速度
- 可以消除 `v_start` 拖尾，同时保留平台段跳算优化
- `safe stop` 仍然只在触发时反推一次刹车距离，不再把动态计算放到每一步里

适用场景：

- 资源极紧
- 低速、短行程
- 调试初期

### 2.2 `trapezoid_curve`

接口：

- [trapezoid_curve_init()](./fc_stp_curve.h#L58)
- [trapezoid_curve_func()](./fc_stp_curve.h#L60)

实现思想：

- 使用标准运动学公式：

```text
v^2 = v0^2 + 2as
```

- 通过“已走距离”和“剩余距离”分别计算加速支路和减速支路速度
- 取二者较小值作为当前命令速度

特点：

- 比 `ladder_curve` 更接近标准梯形
- 平台段、减速切入点更合理
- 已经适合多数常规点到点步进控制

适用场景：

- 想要更标准的梯形速度
- 希望速度曲线更规整
- 负载中等，对冲击不算特别敏感

### 2.3 `s_curve`

接口：

- [s_curve_init()](./fc_stp_curve.h#L78)
- [s_curve_func()](./fc_stp_curve.h#L80)

实现思想：

- 在加速段和减速段使用平滑函数，而不是突变斜率
- 当前实现使用定点 `smoothstep`

```text
f(u) = 3u^2 - 2u^3
```

特点：

- 加速起点和减速终点更柔和
- 机械冲击更小
- 更适合容易共振、负载大、丝杆/皮带等场景

适用场景：

- 对平顺性要求高
- 容易共振
- 想降低噪声和丢步风险

### 2.4 `s_curve_tri_acc`

接口：

- [s_curve_tri_acc_init()](./fc_stp_curve.h#L100)
- [s_curve_tri_acc_func()](./fc_stp_curve.h#L102)

实现思想：

- 同样属于 S 形曲线
- 但加速段采用“分段二次”缓动，而不是 `smoothstep`

```text
u in [0, 0.5]:  y = 2u^2
u in [0.5, 1]:  y = 1 - 2(1-u)^2
```

它的一阶导数为：

```text
y' = 4u              , u in [0, 0.5]
y' = 4(1-u)          , u in [0.5, 1]
```

因此在当前“每步更新一次速度”的离散实现里，表现出来的“加速度”更接近对称三角形。

特点：

- 比 `s_curve` 更强调“加速度对称三角形”的外观
- 中间平台前后的过渡更有“线性上升再线性下降”的感觉
- 仍然保持 S 形速度过渡，不是硬折线梯形

适用场景：

- 想让加速度观感更对称
- 想在 S 曲线和平滑性之间，兼顾更直观的加速度外形
- 希望抓出来的加速度曲线更接近“三角形”而不是“鼓包”

## 3. 参数含义与推荐范围

四套曲线初始化接口风格一致：

```c
curve_init(&curve, v_max, v_start, s_acc);
```

参数含义：

- `v_start`
  启动速度，也是结束速度
- `v_max`
  期望最大速度
- `s_acc`
  期望的加速长度，单位是“步”

推荐整定顺序：

1. 先定 `v_start`
2. 再定 `v_max`
3. 最后调 `s_acc`

### 建议范围

#### `ladder_curve`

- `v_start`：可靠起步速度的 `60%~85%`
- `v_max`：稳定最高速度的 `70%~85%`
- `s_acc`：`100~1000` 步

#### `trapezoid_curve`

- `v_start`：可靠起步速度的 `70%~90%`
- `v_max`：稳定最高速度的 `75%~90%`
- `s_acc`：`150~4000` 步

#### `s_curve`

- `v_start`：可靠起步速度的 `60%~80%`
- `v_max`：稳定最高速度的 `70%~85%`
- `s_acc`：`300~8000` 步

#### `s_curve_tri_acc`

- `v_start`：可靠起步速度的 `60%~80%`
- `v_max`：稳定最高速度的 `70%~85%`
- `s_acc`：`300~8000` 步

与 `s_curve` 相比：

- 如果更看重“加速度对称三角形”的表现，优先 `s_curve_tri_acc`
- 如果更看重整体更圆滑、更柔顺，优先 `s_curve`

## 4. 为什么平台段可以不重复计算

以标准梯形为例，当速度已经达到 `v_target`，并且距离减速点还很远时：

- 下一步速度仍然是 `v_target`
- 下下步速度仍然是 `v_target`
- 直到剩余距离接近减速段之前，命令速度都不会变化

因此在这段平台区间内：

- 不需要每走一步都调用一次 `curve_func(FC_STP_CLAC_NEXT)`
- 也不需要每走一步都调用一次 `freq_set()`

理论上只需要：

1. 第一次进入平台时，把速度设置到平台速度
2. 记录“离减速点还有多少步”
3. 中间这些步直接按原频率继续跑
4. 到接近减速段时再恢复计算

这就是平台段跳算优化的理论基础。

补充说明：

- 对当前版本的 `ladder_curve` 而言，平台段长度可以重新直接使用固定 `s_acc_target`
- 因为“向上取整导致提前到达 `v_target`”的问题，已经在前段/后段离散分配里被消掉了
- 只要剩余距离仍然大于这次运动的减速段长度，就可以安全进入平台段跳算

## 5. 结合 `fc_stp_base` 和 `fc_stp_curve` 的平台段优化实现

### 5.1 base 层新增的通用机制

在 [fc_stp_base_t](./fc_stp_base.h#L123) 中新增了：

```c
size_t curve_hold_steps;
```

含义：

- 未来还有多少个 step 完成后，可以跳过 `curve_func(NEXT)` 和 `freq_set()`

在 [fc_stp_base_heart()](./fc_stp_base.c#L61) 里：

- 如果 `curve_hold_steps > 0`
  - 直接减 1
  - 不调用曲线计算
  - 不重设频率
- 否则
  - 正常调用 `curve_func(FC_STP_CLAC_NEXT, ...)`
  - 如果速度变化，再调用 `freq_set()`

额外处理：

- 启动新运动时清零
- 结束时清零
- `safe stop` 时清零
- 急停时清零

这样可以保证状态切换时不会把平台段优化带到错误的运动阶段。

### 5.2 curve 层如何告诉 base 可以跳算

在 [fc_stp_curve.c](./fc_stp_curve.c#L452) 中新增了一个通用辅助函数：

```c
stp_curve_set_hold_steps(stp, s_remain, s_dec)
```

逻辑：

- `s_remain`：当前剩余步数
- `s_dec`：从平台速度进入减速所需的步数
- 可以跳过的步数约为：

```text
s_remain - s_dec - 1
```

减 1 的原因：

- 需要在“刚好进入减速区”的那个边界点恢复计算
- 不能把减速触发点跳过去

对 `ladder_curve` 的特殊点：

- `ladder_curve` 现在不是靠每步动态计算 `s_stop` 来纠偏
- 而是在进入本次运动时，先把离散加速段拆成前段 `a_now` 与后段 `a_back`
- 其中 `a_back` 默认等于 `a_now - 1`
- `NEXT` 热路径里重新回到了“按当前位置只做一次常量加/减”的形式
- `safe stop` 反推刹车距离也改成了 O(1) 计算，不再二分反查速度
- 所以后续传给 `stp_curve_set_hold_steps()` 的减速段长度又可以回到固定 `s_acc_target`

这样可以保证：

- 平台段跳算不会跨过真正的减速触发点
- 也不会因为 `a_now` 向上取整而人为保留一段无意义的低速尾巴

### 5.3 哪些曲线会使用平台段优化

当前四套曲线都已经接入这个机制：

- [ladder_calc_next()](./fc_stp_curve.c#L318)
- [trapezoid_calc_next()](./fc_stp_curve.c#L551)
- [s_curve_calc_next()](./fc_stp_curve.c#L801)
- [s_curve_tri_acc_calc_next()](./fc_stp_curve.c#L1040)

触发条件共同特点：

- 当前速度已经达到 `v_target`
- 并且剩余步数仍然明显大于减速段长度

这样平台段只在真正“速度不会再变化”的区间里才生效。

## 6. 这样优化后能省掉什么

如果一段运动是标准的“加速 -> 长平台 -> 减速”：

- 加速段仍然每步计算
- 减速段仍然每步计算
- 平台段中间的大量步数将不再重复计算

节省的东西包括：

- 曲线函数运算
- 平台层频率重设调用
- 底层可能存在的定时器重装寄存器写操作

对于长行程、高速、平台段很长的运动，这个优化会比较明显。

## 7. 注意事项

### 7.1 这个优化只适用于“平台速度恒定”的区间

如果未来扩展成：

- 实时改速度
- 在线改目标位置
- jerk 限制的更复杂多段曲线

那么平台段跳算逻辑需要重新评估。

### 7.2 仍然是离散步进系统

即使做了平台跳算：

- 这套控制本质仍然是“每步更新一次速度”
- 不是连续时间域控制

所以：

- 逻分抓出来的速度曲线仍然会有离散特征
- 但平台段优化不会改变轨迹形状，只是减少重复计算

### 7.3 `safe stop` 必须退出平台跳算

这点当前实现已经处理：

- 一旦触发缓停，先清掉 `curve_hold_steps`
- 再进入减速规划

否则可能会出现“本该开始减速却还在跳过计算”的错误。

## 8. 实际选型建议

- 最省算力：`ladder_curve`
- 最标准、最均衡：`trapezoid_curve`
- 最平滑、最适合机械系统：`s_curve`
- 最适合“加速度想看起来更像对称三角形”：`s_curve_tri_acc`

如果项目目标是：

- “先跑起来”：优先 `ladder_curve`
- “轨迹更标准”：优先 `trapezoid_curve`
- “减少冲击/噪声/共振”：优先 `s_curve`
- “想要S曲线, 但加速度外形更接近对称三角形”：优先 `s_curve_tri_acc`

如果行程普遍较长、平台段较多，那么平台段跳算优化值得保留。

## 9. `s_curve` 与 `s_curve_tri_acc` 如何选择

这两套都属于 S 形曲线，但侧重点不同。

### 9.1 选择 `s_curve`

如果你更看重：

- 整体过渡圆滑
- 机械冲击尽量小
- 声音、震动更柔和

优先用 `s_curve`。

它更像“圆滑型 S 曲线”。

### 9.2 选择 `s_curve_tri_acc`

如果你更看重：

- 加速度的外观更接近对称三角形
- 想让中段加速度上升/下降更直观
- 希望抓出来的加速度波形更符合“先线性变大再线性变小”的观感

优先用 `s_curve_tri_acc`。

它更像“对称三角加速度型 S 曲线”。

### 9.3 一个简单的经验

- 机械系统特别娇气、特别怕冲击：先试 `s_curve`
- 你主要在看波形外观，希望加速度更漂亮、更对称：先试 `s_curve_tri_acc`
